# 📁 Лабораторная работа №12: Статические и динамические библиотеки в Си

Лабораторная работа посвящена изучению механизмов связывания (линковки) кода, созданию собственных библиотек и управлению ими в операционных системах семейства Linux.

### 🎯 Задача работы (Что нужно было сделать)
* **Разделение логики**: Вынести вычислительные функции в отдельный модуль (`FuncLab12.c`, `FuncLab12.h`), оставив в `main.c` только интерфейс взаимодействия.
* **Создание статической библиотеки (`.a`)**: Научиться компилировать объектные файлы и упаковывать их в архив с помощью утилиты `ar`. Скомпилировать проект с жестким вшиванием кода библиотеки в бинарник.
* **Создание динамической/разделяемой библиотеки (`.so`)**: Освоить генерацию позиционно-независимого кода (`-fPIC`) и сборку разделяемого объекта (`--shared`). Настроить операционную систему для поиска библиотеки при запуске программы.

---

## 🚀 Инструкция по сборке и запуску

Все команды выполняются в терминале Linux (WSL). Сборка разделена на два независимых сценария.

### Сценарий 1. Сборка и линковка статической библиотеки

1. Компилируем исходные Си-файлы в объектные модули (`.o`):
   ```bash
   gcc main.c -c
   gcc FuncLab12.c -c
   ```
2. Архивируем объектный файл модуля в статическую библиотеку `libMY_LOG.a` (префикс `lib` обязателен):
   ```bash
   ar rc libMY_LOG.a FuncLab12.o
   ```
3. Линкуем исполняемый файл, указывая текущий каталог `.` для поиска библиотеки через флаг `-L`, а имя библиотеки — через флаг `-l`:
   ```bash
   gcc main.o -o static_exe -L. -lMY_LOG
   ./static_exe
   ```
*(Флаг `--static` может потребоваться, если в этой же папке находится динамическая библиотека с таким же именем, так как компилятор по умолчанию выбирает динамическую линковку).*

---

### Сценарий 2. Сборка и запуск динамической библиотеки

1. Компилируем объектный файл модуля с флагом `-fPIC` (Position Independent Code — позиционно-независимый код, необходимый для разделяемых библиотек):
   ```bash
   gcc FuncLab12.c -c -fPIC
   gcc main.c -c
   ```
2. Собираем динамическую библиотеку с помощью флага `--shared`:
   ```bash
   gcc --shared FuncLab12.o -o libMY_LOG.so
   ```
3. Для успешного запуска исполняемого файла операционная система должна знать, где искать `.so` файл. Выберите один из двух способов линковки и запуска:

* **Способ А (Вшивание пути через rpath):**
  Флаг `-Wl,-rpath,.` передает линковщику указание жестко прописать текущую директорию как место поиска библиотеки внутри самого бинарника.
  ```bash
  gcc main.o -o dynamic_exe -L. -lMY_LOG -Wl,-rpath,.
  ./dynamic_exe
  ```

* **Способ Б (Через переменную окружения):**
  Передаем путь к библиотеке непосредственно в момент вызова программы с помощью `LD_LIBRARY_PATH`.
  ```bash
  gcc main.o -o dynamic_exe -L. -lMY_LOG
  LD_LIBRARY_PATH=. ./dynamic_exe
  ```
