## 🛠 Инструментарий и методология отладки

### 1. Интерактивный отладчик GDB
Для работы с отладчиком компиляция должна выполняться с обязательным флагом **`-g`**, который добавляет в бинарный файл отладочные символы (номера строк, имена переменных).

```bash
# Сборка с отладочной информацией
gcc -g task1.c -o debug_task1

# Запуск интерактивной сессии GDB
gdb ./debug_task1
```

**Краткая шпаргалка по консольным командам GDB:**
* `break main` (или `b`) — установить точку останова (breakpoint) на функцию `main` или номер строки.
* `run` (или `r`) — запустить выполнение программы внутри отладчика.
* `next` (или `n`) — выполнить следующую строчку кода без захода внутрь вызываемых функций.
* `step` (или `s`) — сделать шаг вперед с заходом внутрь подпрограмм.
* `print <переменная>` (или `p`) — вывести текущее значение переменной или адреса указателя в памяти.
* `backtrace` (или `bt`) — вывести стек вызовов (критически важно при падении программы в `Segmentation fault`, чтобы узнать, на какой именно строке всё сломалось).
* `quit` (или `q`) — завершить сессию отладки.

### 2. Автоматические валидаторы памяти (Динамический анализ)

При отладке сложных указателей и динамических структур в файле `task_star.c` используются автоматические средства контроля:

#### Способ А. Утилита Valgrind
Позволяет отслеживать использование кучи (Heap) и выявлять утечки памяти (когда память выделили через `malloc`, но забыли освободить через `free`).
```bash
# Запуск детального анализа утечек памяти
valgrind --leak-check=full ./debug_task_star
```

#### Способ Б. Санитайзер адресов (AddressSanitizer / ASan)
Инструмент сборщика, который «на лету» перехватывает ошибки выхода за границы массивов (`Buffer Overflow`) или использование освобожденной памяти (`Use After Free`).
```bash
# Сборка программы со встроенным санитайзером
gcc -g -fsanitize=address task_star.c -o asan_task_star

# Запуск (в случае ошибки программа мгновенно упадет с подробным логом)
./asan_task_star
```
