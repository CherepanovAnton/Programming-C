# 📁 Лабораторная работа №13: Автоматизация сборки проектов (Make и CMake)

Посвящена изучению инструментов автоматизации сборки, управлению зависимостями и кроссплатформенной конфигурации.

### 🎯 Задачи работы
* **Изучение `Make`**: Создание файлов конфигурации `Makefile`, описание целей, реквизитов и правил, использование механизмов инкрементальной сборки.
* **Изучение `CMake`**: Высокоуровневая кроссплатформенная конфигурация проекта через сценарии `CMakeLists.txt`, автоматическая генерация файлов сборки.
* **Реализация подзадач**: Сборка и тестирование модулей `balls-3-and-4`, `ball-5/cmake_task` и `ball-star`.

---

## 🚀 Инструкции по сборке и запуску

В зависимости от используемого инструмента автоматизации в подпапках, выберите соответствующий сценарий сборки:

### Вариант 1. Сборка через CMake (на примере `ball-5/cmake_task`)
Современный кроссплатформенный подход с изоляцией артефактов сборки в отдельной папке `build`.
```bash
# Переходим в директорию с заданием CMake
cd ball-5/cmake_task

# Конфигурация проекта (создание папки build и генерация файлов сборки)
cmake -B build

# Компиляция и линковка проекта
cmake --build build

# Запуск скомпилированного исполняемого файла
./build/main
```

### Вариант 2. Сборка через утилиту Make (на примере `balls-3-and-4`)
Классический подход с компиляцией проекта по правилам, описанным непосредственно в локальном файле `Makefile`.
```bash
# Переходим в директорию с заданием Make
cd balls-3-and-4

# Запуск сборщика (автоматически ищет и выполняет правила из Makefile)
make

# Запуск скомпилированной программы
./main

# Очистка объектных файлов и бинарников после завершения работы
make clean
```
