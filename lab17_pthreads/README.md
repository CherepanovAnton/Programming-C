# 📁 Лабораторная работа №17: Многопоточное программирование на C (POSIX Threads)

Лабораторная работа посвящена детальному изучению жизненного цикла потоков исполнения, механизмов их синхронизации через условные переменные, безопасной отмены и реализации нетривиальных алгоритмов параллельной обработки.

### 🎯 Задача работы (Выполнено на практике)
* **Параллельное исполнение и аргументы**: Организация пула из $N$ потоков, выполняющих общую подпрограмму с изоляцией контекста за счет передачи уникальных структур параметров `threadData` через указатель `void*`.
* **Безопасное прерывание потоков**: Реализация асинхронного закрытия потоков через `pthread_cancel` с развертыванием обработчиков аварийного завершения памяти в стеке очистки `pthread_cleanup_push` / `pthread_cleanup_pop`.
* **Параллельная сортировка (SleepSort)**: Создание распределенного алгоритма сортировки массива со сложностью $O(\max(An))$ за счет управления планировщиком задач операционной системы при помощи системных вызовов `sleep`.
* **Условная синхронизация (Сигнальные переменные)**: Строгая координация очередности вывода главного потока `main` и пула дочерних процессов с использованием пары «Мьютекс + Условная переменная» (`pthread_cond_wait`/`pthread_cond_signal`).

## 📊 Архитектурный базис: Процессы vs Потоки

| Характеристика | Процесс | Поток (Thread / "Легковесный процесс") |
| :--- | :--- | :--- |
| **Память** | Изолирована на уровне ядра ОС. Не разделяет адресное пространство. | Разделяет виртуальную память (кучу, глобальные переменные) процесса. |
| **Создание** | Ресурсоемкое (полное дублирование дескрипторов, контекстов и таблиц страниц). | Легковесное (выделяется только собственный стек выполнения и регистры). |
| **Коммуникация** | Требует явных системных механизмов IPC (pipes, shared memory, message queues). | Прямой обмен данными через общие переменные и области памяти. |
| **Отказ (Крах)** | Сбой внутри одного процесса не влияет на стабильность соседних. | Аварийный сигнал или критическая ошибка в одном потоке убивает весь процесс. |

> **📌 Состояния системных сущностей в Linux:**
> * **Процессы:** `R` (Running), `S` (Interruptible Sleep), `D` (Uninterruptible Sleep), `T` (Stopped), `Z` (Zombie).
> * **Потоки:** Выполняется, Готов к выполнению, Заблокирован (ожидание освобождения примитива), Сон.

## ⚙️ Реализованные механизмы синхронизации и контроля

### 1. Обработка аварийного прерывания (Cleanup Handlers)
Для предотвращения зависания ресурсов или дедлоков при вызове `pthread_cancel` из родительского потока, код защищен регистрацией callback-функций очистки. При получении сигнала отмены поток выполняет стек очистки, гарантируя вызов `killThread`:
```c
pthread_cleanup_push(killThread, &(d->num));
printf("Pthread%d: %s\n", d->num, d->msg);
sleep(3);
pthread_cleanup_pop(0);
```

### 2. Кросс-потоковая синхронизация (Condition Variables)
Для решения задачи строгого чередования фаз вывода (Main 1 -> Pthread 1 -> Main 2 -> Pthread 2...) используется сигнальный флаг и широковещательное уведомление `pthread_cond_broadcast`, исключающее бесконечные итерации и циклы ожидания (спин-локи):
```c
pthread_mutex_lock(&mtx);
while (flag) {
    pthread_cond_wait(&cond, &mtx); // Освобождает мьютекс и засыпает до сигнала
}
printf("Pthread%d: %s\n", d->num, d->msg);
flag = 1;
pthread_cond_signal(&cond);       // Пробуждает поток main
pthread_mutex_unlock(&mtx);
```

## 🚀 Инструкция по компиляции и запуску

При работе с потоками стандарта POSIX компилятору `gcc` необходимо передать директиву **`-pthread`** для корректного связывания исполняемого файла с системной библиотекой:

```bash
# Компиляция многопоточной программы (базовый цикл и SleepSort)
gcc main3.c -pthread -o sleep_sort_demo
./sleep_sort_demo

# Компиляция модуля условной синхронизации по упр. 7
gcc test.c -pthread -o cond_var_demo
./cond_var_demo
```
